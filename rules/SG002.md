# SG002 — Storage mutation after external contract call

| Field    | Value          |
| -------- | -------------- |
| Rule ID  | `SG002`        |
| Severity | high           |
| Category | Reentrancy     |

## Description

Flags an entry point (a `pub fn` inside a `#[contractimpl]` impl block) that
mutates its own contract storage **after** making a cross-contract call,
instead of before it (interaction-then-effect ordering).

This follows the **checks-effects-interactions** pattern: effects (state
writes) should happen before external interactions. If a contract calls out
to another contract and only then updates its own state, a malicious or
upgradeable callee can **re-enter** the caller (e.g. via a callback or
another entry point) before the caller's own state update lands, and observe
or exploit the not-yet-finalized state.

## External call APIs detected (v1)

Verified against the `soroban-sdk` source (`src/env.rs`):

- `env.invoke_contract(&address, &symbol, args)` — panics on failure
- `env.try_invoke_contract(&address, &symbol, args)` — fallible variant
- chained generated-client calls, e.g.
  `PoolClient::new(&env, &pool).swap(&amount)` or
  `pool_module::Client::new(&env, &pool).swap(&amount)` — generated clients
  are thin wrappers around `env.invoke_contract`

> Note: the commonly assumed `env.invoke_contract_check_args` does **not**
> exist in the current `soroban-sdk`.

## Detection (v1)

The check is syntax-level and line-based, reusing the shared analysis
primitives from `crates/core/src/rules/common.rs`:

1. Entry points are discovered exactly as in SG001 (`#[contractimpl]`
   `pub fn`s).
2. Every method call in the body is inspected:
   - **External call** — `env.invoke_contract`, `env.try_invoke_contract`,
     or a chained `...Client::new(...).method(...)` call.
   - **Storage mutation** — the same detection as SG001 (`set`, `put`,
     `remove`, `update`, `try_update`, `extend_ttl`,
     `extend_ttl_with_limits` via an `env.storage()` chain).
3. The function is flagged when the first external call appears on a line
   before a storage mutation.

See `LIMITATIONS.md` for the known v1 constraints (no control-flow or
dataflow analysis).

## Example

Vulnerable (interaction, then effect):

```rust
#[contractimpl]
impl RouterContract {
    pub fn swap(env: Env, caller: Address, pool: Address, amount: i128) -> i128 {
        caller.require_auth();

        // INTERACTION first
        let received = env.invoke_contract::<i128>(&pool, &Symbol::new(&env, "swap"),
            vec![&env, amount.into_val(&env)]);

        // EFFECT second — reentrancy risk
        env.storage().persistent().set(&total_key, &received);
        received
    }
}
```

Safe (effect, then interaction):

```rust
#[contractimpl]
impl RouterContract {
    pub fn swap(env: Env, caller: Address, pool: Address, amount: i128) -> i128 {
        caller.require_auth();

        // EFFECT first — state finalized before interacting
        env.storage().persistent().set(&total_key, &new_total);

        // INTERACTION second
        env.invoke_contract::<i128>(&pool, &Symbol::new(&env, "swap"),
            vec![&env, amount.into_val(&env)])
    }
}
```
